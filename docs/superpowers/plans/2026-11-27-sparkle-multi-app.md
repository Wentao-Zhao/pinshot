# 七应用 Sparkle 接入计划

目标：统一手动更新能力并交付可用 GitHub 更新源；PinShot Esc 仅关闭所属置顶窗口。

- [x] 1. 为各仓库建立功能分支并检查远端版本、运行要求；更新设计与发布配置。
- [x] 2. PinShot Esc 红/绿测试和实现（独立代理）；两组代理为其余六应用接入原生菜单。
- [x] 3. 公共 AppUpdater 封装、Sparkle 固定依赖、rpath、框架嵌入、构建签名，逐项目适配。
- [x] 4. 为每个应用生成并保存独立钥匙串密钥，仅将公钥写入 Info.plist；固定 Release feed URL，关闭自动检查和系统信息上报。
- [x] 5. 完成可复用 appcast 生成与公钥验证脚本及发布流程；失败测试覆盖错误公钥、篡改文件和配置错误。
- [x] 6. 分组运行七应用逻辑检查、动态库/配置启动检查和 DMG 校验；独立审查菜单接入与更新集成质量。
- [x] 7. 临时副本验证手动更新、签名拒绝和 App 替换流程；保留用户已安装应用。
- [x] 8. 各仓库正常钩子提交并推送，发布新版本 DMG 与已签名 appcast，再核验 GitHub 最新附件及 feed。
